# Types, fitting, patterns and flow

## Units

- check a `Program` lazily and query expression types, signatures or bodies → `checkProgram`, `Checker`, `CheckedBody` (`src/compiler/checker/check.ts`)
- get built-in primitive types → `intType`, `floatType`, `boolType`, `stringType`, `unitType`, `neverType` (`src/compiler/checker/types/type.ts`)
- get `errorType`, build a primitive type, or test for a primitive → `errorType`, `primitiveType`, `isPrimitive` (`src/compiler/checker/types/type.ts`); a value expected of the error type reports nothing more → `expectsError`
- stop an operation on an operand with no value: a member read, a method or value call, an index, an operator, a template, a comparison, `await`, `?`, `!`, `??`, `->` on a `Never` (or error-typed) operand → `stoppedOperation` (`src/compiler/checker/calls/stopped-operations.ts`), which gives `Never` and records the operands that run (`CheckedBody.stopsAt`, which lowering's `expression` reads); a pattern on a `Never` part binds its names at `Never` and tests nothing (`takeMatched`, `src/compiler/checker/patterns/walk.ts`); never a per-construct `Never` check
- build or inspect tuple types → `tupleType`, `tupleElements` (`src/compiler/checker/types/type.ts`)
- build or inspect nominal types → `nominalType`, `isNominalEntity` (`src/compiler/checker/types/type.ts`)
- build a shape (an anonymous struct type, the value behind a shared struct included), its fields in name order → `shapeType` (`src/compiler/checker/types/type.ts`); never write `{ kind: 'anonymous', … }` by hand
- a struct's fields as laid out, nominal or shape, in name order (§3.1 "Field order") → `checker.fieldsOf` (`src/compiler/checker/declarations/layout.ts`); as declared, in declaration order, which only evaluation follows (a literal's sources, defaults) → `declaredFieldsOf`; any list of fields in that one order → `inFieldOrder`; values given by field name laid out in a struct's order, and back → `laidOut`, `namedValues` (`src/compiler/checker/types/field-order.ts`)
- the shape a nominal struct's value converts into (none for an annotated field) → `Fitting.shapeOf` (`src/compiler/checker/types/fit.ts`), answered by `Layouts.nominalShapeOf` (`src/compiler/checker/declarations/layout.ts`); the conversion is a `Fit` of kind `shape`, ranked with `reshapes`
- the field a field's declaring node declares, given its owner (a struct, an enum, a shape's `{…}` type, a trait) → `declaredFieldOf` (`src/compiler/checker/types/declared-fields.ts`)
- the type an extern or top-level constant's declaration gives it, outside any body → `declaredOutsideBodies` (`src/compiler/checker/expressions/names.ts`)
- inspect or attach variadic type packs on function types → `isPack`, `fillsPack`, `packRestSlot` (`src/compiler/checker/types/type.ts`), `withPack`; compare function types' shapes → `sameShape`, `functionFits` (`src/compiler/checker/types/function-types.ts`)
- compare two types or constraints for equality or fit → `sameType` (key equality, the one definition of identity), `sameConstraint`, `isAssignable` (`src/compiler/checker/types/identity.ts`); two function types' parameters and results, or a function fitting another's header → `sameShape`, `functionFits` (`src/compiler/checker/types/type.ts`)
- inspect or map a type's direct child types → `typeChildren`, `mapChildren` (`src/compiler/checker/types/type-parts.ts`)
- list type parameters, nominal or `any` types in a `Type` → `parametersIn`, `nominalsIn`, `anyTypesIn`, `mentionsError` (`src/compiler/checker/types/type-parts.ts`)
- decide whether generic uses would instantiate endlessly (§3.5): build a use's edges, then find the expanding ones on a cycle among those reached from the nodes judged, giving each node's edges and the node an edge leads to → `argumentEdges`, `endlessEdgesFrom` (`src/compiler/checker/types/expansion-edges.ts`); a new kind of generic use (calls, fields, later alias reductions) supplies its own nodes, never a walk of its own
- drop refinements (such as `sendable` on function types) at any depth → `widened` (`src/compiler/checker/types/widening.ts`)
- tell whether a result computed again has types alike in every part (aliases, nodes written at, an `any`'s constraint and a union's member order included) → `sameTypeSpelled` (`src/compiler/checker/types/type-parts.ts`), defined by `typeKeys.spelledKey` (`src/compiler/checker/types/type-keys.ts`); keep a result computed from a type's spelling (a type `match` reduction) by `spelledKey`, never `typeKey`, since an entry's key must decide its context (`structures/entries`)
- strip every alias from a type, giving the type its key names, so a result kept by key never depends on its first asker's spelling → `unaliased` (`src/compiler/checker/types/type-parts.ts`)
- spell a `Type` as written, through its alias, associated type or keys spelling if it has one, for messages → `typeText`; and, for what a tool shows, with what that spelling names beside it (`keyof Settings = "region" | "retries"`) → `writtenAndNamedText` (`src/compiler/checker/types/type-text.ts`)
- spell a function type in parts (head, each parameter, tail), or a parameter's type with its `&` → `functionTypeParts`, `slotText` (`src/compiler/checker/types/type-text.ts`)
- show a function as an editor does, its signature with where each parameter stands in it → `signatureOf`, `functionTypeSignature` (`src/language-service/signatures.ts`)
- give a type the spelling it was written through, an alias, an associated type, or a struct's keys (`keyof S` reduced keeps `{kind: 'keys', of}`, which tools read to tell a key's struct) → `aliasedAs` (`src/compiler/checker/types/type.ts`); `substitute` keeps it, `widened` drops it where it widens
- get a canonical key for a `Type` or numeric identity for an object → `typeKeys.typeKey`, `typeKeys.identityOf` (`src/compiler/checker/types/type-keys.ts`)
- keep a program-wide checker result (cached, cycle-aware, its diagnostics kept with it) → `checker.entries.table()` (`EntryTable`, `src/structures/entries/index.ts`); report through `checker.report`, inside an entry
- read a module's diagnostics, or check one top-level item whole before reading what checking decided in it → `checker.diagnosticsOf`, `checker.checkItem` (`src/compiler/checker/declarations/module-checks.ts`)
- guard a recursive walk over a type's parts (`Sendable`, JSON codecs, `heldType`) against cycles → `TypeCycle` (`src/compiler/checker/types/type-cycle.ts`); never a visited set of your own (a walk that must end at a declaration whatever its arguments, as finiteness does, keys by declaration instead: `types/finiteness.ts`)
- build or apply a type substitution → `substitutionFor`, `substitute`, `substituteAny`, `substituteKept` (`src/compiler/checker/types/substitution.ts`), each taking the program's `TypeRules`
- the rules building a type needs of the program, which `types/` sits below (whether an `any` member takes a member whole; an associated type `T.Data`, a field's type `S[K]`, a struct's keys `keyof S`, a mapped struct type and a use of a type `match` alias reduced once their parts are known, the shape a recursive type `match` use stands for; whether a written key is one of a struct's) → `TypeRules` (`src/compiler/checker/types/type-rules.ts`), implemented once by `ProgramChecker.typeRules` (each answer an entry, a cycle answering `false`), read as `Checker.typeRules`, and by `Fitting`, which extends it
- view a `CheckedBody` with all recorded types substituted for one instantiation → `instantiatedBody` (`src/compiler/checker/types/instantiation.ts`)
- decide `==`, `!=` or `is` by its operands' types (§4), warning once where it stands, and a condition built of them → `checkEquality`, `decideComparison`, `decidedValue` (`src/compiler/checker/rules/decided-conditions.ts`), recorded through `BodyContext.decide`/`decidedAt`/`ruleOut` and read as `CheckedBody.decidedOf`/`isRuledOut`, which lowering's `if`, `match`, `==` and `is` honour
- what types say of the literals a value may be, whether two sides are always or never equal → `decidedEquality`, `isKnown` (`src/compiler/checker/types/known-literals.ts`): the one literal-set rule comparisons and patterns share, never a second
- a pattern its part's type can't hold (§3.11) → a `never` test (`neverTest`, `cantMatch` in `src/compiler/checker/checked-pattern.ts`), made where a pattern selects (`ruledOutSelection`) or compares (`ruledOutLeaf`, `src/compiler/checker/patterns/pattern-tests.ts`); a match case that `cantMatch` is ruled out and warned of (5422), an or-pattern drops such an alternative; never an error for it beside it
- keep what checking records of a node per pass of a field loop (§4), so a body reads as each pass checked it → a `PassTable` from the body's `Passes` (`src/compiler/checker/passes.ts`); a new per-node record of a body unit is one of its tables, never a plain `Map`, unless it holds of every pass (a variable changing, a label's target); a pass's diagnostics wait for the loop to settle (`hold`, `settled`); read a loop's passes → `CheckedBody.passesOf`, the passes a field loop runs over a type → `fieldPassesOver` (`src/compiler/checker/traits/struct-keys.ts`), each saying which fields it visits (`PassVisits`: one field, the others, or none: a struct with no field or a value of type `Never`, checked once as code that never runs, its key and value `Never`), which a consumer dispatches on, never on a missing name; check a construct over a struct's fields (a field loop, an array or a struct comprehension) → `checkedFieldPasses` then `inFieldPasses` (`src/compiler/checker/rules/field-passes.ts`), and record back in each pass what all of them decide together (an agreed element type, inferred type arguments) → the `CheckedPasses.inEach` it returns, never a record made outside the passes; which constructs run over fields and what their passes check → `OverFields`, `isOverFields`, `passedParts` (`src/compiler/syntax/statements.ts`); tools' view of a node inside one → `passesAround` (`src/compiler/checker/lookup/pass-views.ts`, read by `bodyHolding`); a struct comprehension's fields, against a declared shape, a type not all known or no type → `checkComprehended`, `checkOpaqueComprehended`, `freshComprehended` (`src/compiler/checker/expressions/struct-comprehensions.ts`), its one `FieldSource` of kind `comprehension`
- build or unwrap `Future<T>` or `Array<T>`, → `futureOf`, `futureArgument`, `arrayOf`, `arrayElement` (`src/compiler/checker/types/well-known.ts`)
- build or unwrap any well-known type (`src/language/well-known.ts`) → `wellKnownOf`, `wellKnownArguments` (`src/compiler/checker/types/well-known.ts`)
- whether `==`, `!=` and a literal pattern compare two types, recording a side's conversion → `fitEqualSides`, `comparable` (`src/compiler/checker/types/equality.ts`): one rule for both
- build a union normalized (flattened, duplicates, `Never`, literals into bases, `true | false` as `Bool`, members an `any` member takes whole), `T?`, or a literal type → `unionOf`, `optionalOf` (both taking `TypeRules`), `literalType`, `literalOrBase` (`src/compiler/checker/types/unions.ts`); what remains of a normalized union's members, or its members spelled again → `unionOfNormalized`; never write `{ kind: 'union', … }` by hand
- take a union apart: its members, `T` of `T?`, what remains without some members, a member it holds, a literal's base, whether a member has one value only, the `any` member taking a member whole, the recursive member whose union holds a member (`Tree | String` holds `Int`) → `membersOf`, `optionalInner`, `hasMember`, `baseOf`, `hasOneValue`, `absorbingMember`, `holdingMember` (`src/compiler/checker/types/unions.ts`); what a value is where it isn't `none`, for every type that may hold `none` (an optional, `None`, a type whose `any` member took `None`), as `??`, `?.`, `!` read it, a recursive use left unfolded → `presentType` (same file); the members a literal selects, through an `any` or recursive member too → `literalMembers` (`named-types.ts`)
- tell a value converting into several members of a union apart from a mismatch → `intoSeveral` (`src/compiler/checker/types/fit.ts`)
- narrow an expected union to the member a directly built value takes, or a literal whose own type misses the union can be built as (`[1, [2]]` against `Json`; an empty `[]` the array member), at any depth of unions inside unions → `memberBuilt` (`src/compiler/checker/types/expected.ts`), which `BodyContext.expression` runs for every expression through `builtMember` and `builtAsChecked` (`expressions/built-members.ts`), before checking: a collection literal with an item only checking types (`[1 + 1, "a"]`) by its shape (`openBuildsOf`, `collectionOpenBuilds`), each item then checked against the member's item, unless an `any` member might take it whole; and, for a tuple or struct literal whose items only checking types (`(1 + 1, none)`), again from its checked items, rebuilding it; an `Accepts` taking a recursive use as what it unfolds to, and any union by one member, at any depth → `takingUnfolded` (same file), applied where an `Accepts` is made (`acceptsOf`, `buildsOf`, `openBuildsOf` in `expressions/expressions.ts`), never by its readers
- recursive aliases (§3.17): which top-level aliases refer to themselves, guarded or not, and whether they are regular, read from their bodies' syntax before any type resolves, and whether a body is a union as written → `AliasRecursions` (`src/compiler/checker/declarations/alias-recursion.ts`); a recursive alias stands for its own `RecursiveType`, its body resolved apart and unfolded per use (`Aliases.unfold`), reached only through `TypeRules.unfold` (any recursive use, a type `match`'s too) and `TypeRules.unfoldedMembers` (what a union holding one merges into it, `unionOf`); whatever an unfolding gives, a tuple, function or nominal type as much as a shape or a union, carries the use's identity (`Unfolding`, `recursionOf`, `withoutRecursion` in `type.ts`; `withRecursion`, `computed-types.ts`), so `typeKey(unfold(use)) === typeKey(use)` and it keys, prints, substitutes and owns statics as the use (`TypeKeys.recursionKey`); a use and its body written out go where the other is expected at the top only (`asValue` in `fit.ts`: a shape by the shape conversion, a tuple's, function's or nominal type's value as it is); finiteness of one → `checkFiniteAlias` (`src/compiler/checker/declarations/struct-rules.ts`) over `holdsItself` (`types/finiteness.ts`)
- decide what an indented value builds (an array, a map or a struct) from its `T` or the expected type, and check it as that literal → `checkIndentedValue`, `indentedAccepts` (`src/compiler/checker/expressions/indented-values.ts`); never a second meaning-by-type rule
- take an expected type apart for a value built from it (a struct, tuple, array or map literal, a lambda, a function value, a bare variant or fieldless generic struct, lambdas inferred inside an argument) → `builtFrom`, `expectedTuple`, `collectionTarget`, `expectedFunction`, `sameNominal`, `enumsExpected`, `expectedNominal` (`src/compiler/checker/types/expected.ts`), each past `None` and unfolding a recursive use; never strip the expected optionals or unfold in a construct

- what an or-pattern's alternatives bind and select between them → `sameNames`, `partSelected` (`src/compiler/checker/patterns/alternatives.ts`); an array pattern's items → `takeArray` (`patterns/arrays.ts`)
- the literal type a literal written in place has (a string, a Bool, a maybe negated integer) → `writtenLiteral` (`src/compiler/checker/types/unions.ts`); the type it has where a type is expected → `literalOrBase`, or against a parameter still inferred → `Inference.literalType`
- the union a member parameter (`T in U`) stands for one member of: as written where it is declared → `CheckerContext.memberUnionOf` (`src/compiler/checker/context.ts`); as an occurrence ranges over it, a mapped entry's parameter carrying its type's own substituted keys (`TypeParameterType.within`) → `Fitting.memberUnionOf`, which every reader holding the type uses, never the declaration's; whether a type is one, standing for one member → `isMemberParameter` (`src/compiler/checker/types/type.ts`); how one compares by `==` and literal patterns, as the member each instantiation makes it → `fitEqualSides` (`types/equality.ts`), and what its cases cover → `signatureOf` (`patterns/shapes.ts`); whether a type, one naming type parameters included, may stand for one, inferred or written → `isOneMember`, and checked with a report → `standsForMember` (`src/compiler/checker/types/member-arguments.ts`)
- list names bound by a checked pattern → `namesBound` (`src/compiler/checker/checked-pattern.ts`)
- step from a pattern's part to a part of it → `PartStep` (`src/compiler/checker/checked-pattern.ts`): a tuple element or a variant's field by position, a union member's value (`member`, carrying its union and member, which an instantiation may collapse, or let an `any` member take whole, lowering deriving where it reads), an `any`'s held value (`downcast`), an array's length, item or rest, or a struct step (`StructStep`): a struct's field by name (`FieldStep`, built by `structFieldStep`), whose position the struct type as instantiated decides, or a struct pattern's rest (`fieldRest`, §3.11); never a position standing for a member's or `any`'s value, nor for a struct's field. A target's and an assignment's path is `TargetStep`s: positions and struct steps
- take a struct pattern apart over a struct whose fields aren't known yet, by its fields' names, and type its rest → `isStructNotKnown`, `takeFieldsByName`, `restBinding` (`src/compiler/checker/patterns/struct-fields.ts`); a rest's type is the mapped struct type of the keys left (`TypeRules.keysOf`, `mappedType`), never built by hand
- run forward data-flow analysis over a body → `flowThrough`, `FlowRule` (`src/compiler/checker/flow/forward.ts`)

## One-way rules

- Fit every value through `BodyContext.expect` / `fit` (`fitWritten` for assignments, `fitUnwrapped` for spreads) so conversions are recorded once.
- Every type built from parts the program judges (a union written, substituted, joined, made optional or widened; a computed type substituted) is built through the constructors taking `TypeRules` (`mapChildren` rebuilds both), so it is normalized alike however it was reached; never normalize after the fact, and never store the rules in a type or a substitution, which a later checker takes over.
- Recognize well-known types by binder entity via `src/compiler/checker/types/well-known.ts`, never by declaration name string; an optional is a union holding `None` (`optionalInner`, `unions.ts`), and whether a value may be `none` is `presentType`'s, never a check for a `None` member.
- Key types and identities through `checker.typeKeys` (`src/compiler/checker/types/type-keys.ts`), whose numbers are the module's, alike in every checker; never write those numbers into lowering's output.
- Every pattern goes through `src/compiler/checker/patterns/walk.ts`, and every body flow rule goes through `flowThrough` (`flow/forward.ts`).
- A struct's fields are laid out in name order alone (`fieldsOf`, `inFieldOrder`); a value built field by field in another order takes its layout by the fields' names (`laidOut`), never by position.
