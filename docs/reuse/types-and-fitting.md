# Types, fitting, patterns and flow

## Units

- check a `Program` lazily and query expression types, signatures or bodies → `checkProgram`, `Checker` (`src/compiler/checker/check.ts`), `CheckedBody` (`src/compiler/checker/surface/checked-body.ts`)
- get built-in primitive types → `intType`, `floatType`, `boolType`, `stringType`, `unitType`, `neverType` (`src/compiler/checker/types/type/primitives.ts`)
- get `errorType`, build a primitive type, or test for a primitive → `errorType`, `primitiveType`, `isPrimitive` (`src/compiler/checker/types/type/primitives.ts`); a value expected of the error type reports nothing more → `expectsError`
- stop an operation on an operand with no value: a member read, a method or value call, an index, an operator, a template, a comparison, `await`, `?`, `!`, `??`, `->` on a `Never` (or error-typed) operand → `stoppedOperation` (`src/compiler/checker/resolution/calls/stopped-operations.ts`), which gives `Never` and records the operands that run (`CheckedBody.stopsAt`, which lowering's `expression` reads); a pattern on a `Never` part binds its names at `Never` and tests nothing (`takeMatched`, `src/compiler/checker/constructs/patterns/walk/index.ts`); never a per-construct `Never` check
- build or inspect tuple types → `tupleType`, `tupleElements` (`src/compiler/checker/types/type/primitives.ts`)
- build or inspect nominal types → `nominalType`, `isNominalEntity` (`src/compiler/checker/types/type/index.ts`)
- build a shape (an anonymous struct type, the value behind a shared struct included), its fields in name order → `shapeType` (`src/compiler/checker/types/type/index.ts`); never write `{ kind: 'anonymous', … }` by hand
- a struct's fields as laid out, nominal or shape, in name order (§3.1 "Field order") → `checker.fieldsOf` (`src/compiler/checker/constructs/declarations/layout/index.ts`); as declared, in declaration order, which only evaluation follows (a literal's sources, defaults) → `declaredFieldsOf`; any list of fields in that one order → `inFieldOrder`; values given by field name laid out in a struct's order, and back → `laidOut`, `namedValues` (`src/compiler/checker/types/type/field-order.ts`)
- the shape a nominal struct's value converts into (none for an annotated field) → `Fitting.shapeOf` (`src/compiler/checker/types/fitting/fit/index.ts`), answered by `Layouts.nominalShapeOf` (`src/compiler/checker/constructs/declarations/layout/index.ts`); the conversion is a `Fit` of kind `shape`, ranked with `reshapes`
- the field a field's declaring node declares, given its owner (a struct, an enum, a shape's `{…}` type, a trait) → `declaredFieldOf` (`src/compiler/checker/types/written/declared-fields.ts`)
- the type an extern or top-level constant's declaration gives it, outside any body → `declaredOutsideBodies` (`src/compiler/checker/constructs/expressions/access/names.ts`)
- build a function type (every builder and rebuilder, a pack flattened where a tuple fills it) → `functionType`; the type `Fn<Args, Result, Kind, Send>` names, its tuple's `&T` items by reference → `fnType`; the `Send` a head writes, whether a function is sendable, and the modifiers a function type prints → `sendOf`, `isSendableFunction`, `modifiersOf`; a `Send` fitting another by `Sendability`'s order → `sendFits`; either qualifier order itself, below, join and bottom, as fitting and inference compare a mark or a sendability → `markOrder`, `sendabilityOrder`; whether two marks are one as written, where identity can't be reached → `sameMark` (`src/compiler/checker/types/type/mark-orders.ts`); a mark's or a sendability's literal → `markType`, `sendType` (`src/compiler/checker/types/type/primitives.ts`); the simple mark, and whether a mark is it, a mark variable (a mark parameter or a member-bounded associated type, `Self.Mode`) or one of the two kinds → `simpleMark`, `isSimpleMark`, `isMarkVariable`, `isOneKind`; whether a type parameter stands for a mark, any or one of the two kinds → `isMarkParameter`, `standsForAnyMark`, `standsForOneKind` (`src/compiler/checker/types/type/function-kinds.ts`); what a type parameter, or a call's twin of one, qualifies functions by, its order and whether it may be the bottom → `Fitting.qualifierOf` (`src/compiler/checker/types/properties/qualifiers.ts`); a function made async, or the future's value a function giving none goes into → `madeAsync`, `resolvedInto`; inspect variadic type packs on function types → `isPack`, `fillsPack`, `packRestSlot`; whether a type is a function taking nothing, as a deferred call's function is → `takesNothing`; what a head's call gives, an async one's a future → `headResult`; how a function's result fits another's, as a value or into a future's value → `resultFitOf` (`src/compiler/checker/types/type/function-types.ts`); the program's futures as a seam → `futuresOf` (`src/compiler/checker/types/type/well-known.ts`)
- compare two types or constraints for equality or fit → `sameType` (key equality, the one definition of identity), `sameConstraint`, `isAssignable` (`src/compiler/checker/types/identity/identity.ts`); two function types' parameters and results, or a function fitting another's header → `sameShape`, `functionFits` (`src/compiler/checker/types/type/function-types.ts`)
- inspect or map a type's direct child types → `typeChildren`, `mapChildren` (`src/compiler/checker/types/parts/type-parts.ts`)
- list type parameters, nominal or `any` types in a `Type` → `parametersIn`, `nominalsIn`, `anyTypesIn`, `mentionsError` (`src/compiler/checker/types/parts/type-parts.ts`)
- decide whether generic uses would instantiate endlessly (§3.5): build a use's edges, then find the expanding ones on a cycle among those reached from the nodes judged, giving each node's edges and the node an edge leads to → `argumentEdges`, `endlessEdgesFrom` (`src/compiler/checker/rules/expansion/edges.ts`); a new kind of generic use (calls, fields, later alias reductions) supplies its own nodes, never a walk of its own
- drop refinements (such as `sendable` on function types) at any depth → `widened` (`src/compiler/checker/types/unions/widening.ts`)
- tell whether a result computed again has types alike in every part (aliases, nodes written at, an `any`'s constraint and a union's member order included) → `sameTypeSpelled` (`src/compiler/checker/types/parts/type-parts.ts`), defined by `typeKeys.spelledKey` (`src/compiler/checker/types/identity/type-keys.ts`); keep a result computed from a type's spelling (a type `match` reduction) by `spelledKey`, never `typeKey`, since an entry's key must decide its context (`structures/entries`)
- strip every alias from a type, giving the type its key names, so a result kept by key never depends on its first asker's spelling → `unaliased` (`src/compiler/checker/types/parts/type-parts.ts`)
- spell a `Type` as written, through its alias, associated type or keys spelling if it has one, for messages → `typeText`; and, for what a tool shows, with what that spelling names beside it (`keyof Settings = "region" | "retries"`) → `writtenAndNamedText` (`src/compiler/checker/types/type/type-text.ts`)
- spell a function type in parts (head, each parameter, tail), or a parameter's type with its `&` → `functionTypeParts`, `slotText` (`src/compiler/checker/types/type/type-text.ts`)
- show a function as an editor does, its signature with where each parameter stands in it → `signatureOf`, `functionTypeSignature` (`src/editor/language-service/signatures/signatures.ts`)
- give a type the spelling it was written through, an alias, an associated type, or a struct's keys (`keyof S` reduced keeps `{kind: 'keys', of}`, which tools read to tell a key's struct) → `aliasedAs` (`src/compiler/checker/types/type/alias-uses.ts`); `substitute` keeps it, `widened` drops it where it widens
- tell a handle from a value by its declaration, never its name (§2, §3.6): whether a type's values are handles → `isHandleType`; whether its handles stay in their instance or process, never sendable and the only kind a `dispose` may make disposable → `isConfined` (`src/compiler/checker/types/properties/handles.ts`)
- get a canonical key for a `Type` or numeric identity for an object → `typeKeys.typeKey`, `typeKeys.identityOf` (`src/compiler/checker/types/identity/type-keys.ts`)
- keep a program-wide checker result (cached, cycle-aware, its diagnostics kept with it) → `checker.entries.table()` (`EntryTable`, `src/foundation/structures/entries/index.ts`); report through `checker.report`, inside an entry

- guard a recursive walk over a type's parts (`Sendable`, JSON codecs, `heldType`) against cycles → `TypeCycle` (`src/compiler/checker/types/properties/type-cycle.ts`); never a visited set of your own (a walk that must end at a declaration whatever its arguments, as finiteness does, keys by declaration instead: `types/properties/finiteness.ts`)
- build or apply a type substitution → `substitutionFor`, `substitute`, `substituteAny`, `substituteKept` (`src/compiler/checker/types/parts/substitution.ts`), each taking the program's `TypeRules`
- the rules building a type needs of the program, which `types/` sits below (whether an `any` member takes a member whole; an associated type `T.Data`, a field's type `S[K]`, a struct's keys `keyof S`, a mapped struct type and a use of a type `match` alias reduced once their parts are known, the shape a recursive type `match` use stands for; whether a written key is one of a struct's) → `TypeRules` (`src/compiler/checker/types/type/type-rules.ts`), implemented once by `ProgramChecker.typeRules` (each answer an entry, a cycle answering `false`), read as `Checker.typeRules`, and by `Fitting`, which extends it
- view a `CheckedBody` with all recorded types substituted for one instantiation → `CheckedBody.instantiated` (`src/compiler/checker/surface/checked-body.ts`), each part substituted by `instantiationBy` (`src/compiler/checker/wiring/body/facts/instantiation.ts`)
- add a fact a checked body answers → a member of `BodyFacts` (`src/compiler/checker/surface/checked-body.ts`) and its one entry in `bodyFacts` (`src/compiler/checker/wiring/body/facts/index.ts`): how it is read at a pass, how an instantiation reads it, how a field loop's passes join it (a join from `src/compiler/checker/wiring/body/facts/pass-joins.ts`); never an accessor, substitution or join written elsewhere

## One-way rules

- Fit every value through `BodyContext.expect` / `fit` (`fitWritten` for assignments) so conversions are recorded once.
- Every type built from parts the program judges (a union written, substituted, joined, made optional or widened; a computed type substituted) is built through the constructors taking `TypeRules` (`mapChildren` rebuilds both), so it is normalized alike however it was reached; never normalize after the fact, and never store the rules in a type or a substitution, which a later checker takes over.
- A type rebuilt with no part changed is the very object (`mapChildren` and `mapParts` in `types/parts/type-parts.ts`, `mapAliasUse` in `types/type/alias-uses.ts`, substitution), never a copy: keys, parameters and other derived facts are memoized per type object, and a copy recomputes them all, a recursive union's term-graph minimization included. Only a computed type is built again whatever its parts, since a use left unreduced reduces then. A canonical key is built once per structure whatever the object: kept by the type's pre-key, its structure down to the recursive nodes it reaches (`keptCanonicalKey`, `types/identity/type-keys.ts`), so a new object of a structure keyed before costs its spine, never a term graph.
- Recognize well-known types by binder entity via `src/compiler/checker/types/type/well-known.ts`, never by declaration name string; an optional is a union holding `None` (`optionalInner`, `types/unions/unions.ts`), and whether a value may be `none` is `presentType`'s, never a check for a `None` member.
- Key types and identities through `checker.typeKeys` (`src/compiler/checker/types/identity/type-keys.ts`), whose numbers are the module's, alike in every checker; never write those numbers into lowering's output.
- Every pattern goes through `src/compiler/checker/constructs/patterns/walk/index.ts`, and every body flow rule goes through `flowThrough` (`rules/flow/forward.ts`).
- A struct's fields are laid out in name order alone (`fieldsOf`, `inFieldOrder`); a value built field by field in another order takes its layout by the fields' names (`laidOut`), never by position.
