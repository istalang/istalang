# Syntax trees and traversal

## Units

- scan a `SourceText` into tokens, comments and diagnostics → `scan` (`src/compiler/scanner/scan.ts`)
- parse a `SourceText` and `ScanResult` into a `SyntaxTree`, keeping a previous tree's nodes for every segment an edit left alike → `parse` (`src/compiler/parser/parse.ts`)
- print a `SyntaxTree`, a `SourceText` or a text in the canonical format, refusing one with syntax errors → `formatTree`, `formatSource`, `formatText` (`src/formatter/format.ts`)
- print a list in brackets, on one line or one item per line with no `,` → `bracketed` (`src/formatter/layout/lists.ts`); a list whose brackets only its broken form needs, as a bare import's names → `bracketedWhenBroken`; which children stand in brackets → `standingIn` (`src/formatter/layout/brackets.ts`)
- read a tree's tokens again, all of them or only its code's, or the bracket closing each opening one → `allTokensOf`, `codeTokensOf`, `closingBracketsOf` (`src/editor/language-service/reading/tokens.ts`)
- pair a token list's brackets as the parser does, and find where each one left open ends → `pairBrackets` (`src/compiler/parser/cursor/brackets.ts`)
- check whether a word is a reserved or contextual keyword → `isKeyword`, `isContextualWord`, `keywords`, `punctuators` (`src/compiler/syntax/tokens/index.ts`)
- know a head's modifiers (a function's, a function type's, a lambda's, an extern's, a shared struct's): their groups in print order, the groups each form takes, what may follow one, a function's qualifiers, whether a head is async (read it nowhere else), and their text in print order, a named mark (`M fn`) in its kind's place → `modifierGroups`, `ModifierWord`, `headForms`, `groupIn`, `followersIn`, `FunctionQualifiers`, `qualifiersOf`, `awaits`, `modifiersText` (`src/compiler/syntax/tokens/modifiers.ts`); a named type's path as written (`Self.Mode`) → `namedTypeText` (`src/compiler/syntax/types/index.ts`); parse one, a declared function's with the mark it names, or look past one to its keyword → `parseHead`, `parseFunctionHead`, `headAhead` (`src/compiler/parser/grammar/parts/heads.ts`)
- list the words a grammar position dispatches on: a declaration's, a statement's, an operand's, a type's or a pattern's start, what goes on after an operand, and what follows each modifier → `declarationWords`, `statementWords`, `operandWords`, `infixWords`, `typeWords`, `PatternWord`, `followers` (`src/compiler/syntax/tokens/grammar-words.ts`); what a module's item starts with → `moduleItemWords` (`src/compiler/syntax/items.ts`)
- key a parser table by those words, checked both ways by type, read a contextual word's parselet, or ask whether a modifier's follower comes next → `StartParselets`, `WordParselets`, `wordParseletAt`, `followsModifier` (`src/compiler/parser/grammar/word-parselets.ts`)
- parse the `case` of a `match`, a `select` or a type `match`, a line not starting with one skipped whole → `parseCase` (`src/compiler/parser/grammar/parts/cases.ts`); an alias's or associated type's body, a type or a type `match` → `parseAliasBody` (`src/compiler/parser/grammar/declarations/type-matches.ts`); the `infer` variables a case's pattern declares → `inferTypesIn` (`src/compiler/syntax/types/type-matches.ts`)
- where a node stands among type `match`es — in a case's pattern (the one place `infer` may stand, which the checker and completion both read), elsewhere inside one, or outside — and the `infer` types a pattern holds → `matchPlaceOf`, `inferTypesIn` (`src/compiler/syntax/types/type-matches.ts`)
- parse a grammar whose operators bind at a few fixed levels, as patterns and types do → `leveledGrammar`, `LeveledParselet` (`src/compiler/parser/grammar/parts/levels.ts`)
- read the literal a token denotes, the literal at the cursor, or a negative number where a literal stands alone → `literalFrom`, `parseLiteral`, `parseNegativeLiteral`, `Negatable` (`src/compiler/parser/grammar/parts/literals.ts`)
- get the last identifier of a `QualifiedName` or check for a missing identifier → `lastName`, `isMissingName` (`src/compiler/syntax/tree/node.ts`)
- list a syntax node's direct children in source order, its field children alone, or a function's body → `childrenOf`, `fieldChildrenOf`, `bodyOf`, `isNode` (`src/compiler/syntax/tree/index.ts`); a struct's or an enum's members as written, associated types among them → `membersAsWritten` (`src/compiler/syntax/declarations/index.ts`)
- parse what follows `is`: a trait or a struct constraint, several joined by `&` → `parseConstraints` (`src/compiler/parser/grammar/parts/constraints.ts`); its tree → `ConstraintNode`, `StructConstraint`, `FieldEntry` (`src/compiler/syntax/types/index.ts`)
- check whether an item may stand in a module or a block → `allowedInModule`, `allowedInBlock` (`src/compiler/syntax/items.ts`)
- find a node's parent, the nodes holding it from it to the root, or the nodes holding an offset from the root to the innermost → `parentOf`, `ancestorsOf`, `nodesAt` (`src/compiler/syntax/tree/index.ts`)
- read where a node stands in the text: its own span → `spanIn`; it and everything under it, through a function's body or a trait's members → `extentIn` (`src/compiler/syntax/tree/positions.ts`, `src/compiler/syntax/tree/index.ts`)
- join or compare spans of one segment: first to last, covering several, what parts two, the empty span at an end, containment, one place → `spanAcross`, `spanCovering`, `spanBetween`, `endOf`, `encloses`, `startTogether` (`src/compiler/syntax/tree/positions.ts`)
- turn a phase's anchored diagnostic into one at text positions as it leaves → `diagnosticIn` (`src/compiler/syntax/tree/positions.ts`)
- the text a lambda or local function covers, header and body → `nestedFunctionSpan` (`src/compiler/syntax/declarations/index.ts`); lowering's, from the tree → `nestedSpanOf` (`src/compiler/lowering/functions/bodies.ts`)
- list a node and every node under it in source order, each before its children (explicit stack) → `nodesUnder` (`src/compiler/syntax/tree/index.ts`)
- list direct children that run in the same function body where they stand (skipping nested functions, and the call a deferred call makes later, though not what it computes now) → `bodyChildrenOf`, `nestsFunction` (`src/compiler/syntax/tree/index.ts`); the one home of "runs now", which every walk asking it reads
- look up operator precedence, associativity and meaning → `binaryOperators`, `unaryOperators`, `operatorLevels` (`src/compiler/syntax/expressions/operators.ts`)
- classify operators or unwrap a compound assignment's operator → `isAssignmentOperator`, `compoundOperator` (`src/compiler/syntax/expressions/operators.ts`)
- test whether a token kind is a comparison or chaining operator, or one calling `compare`/`includes` → `isComparisonOperator`, `isChainingOperator`, `isImplicitOperator` (`src/compiler/syntax/expressions/operators.ts`)
- compute precedence levels for operator parsing and printing → `tighterLevel`, `rightOperandLevel`, `bindingPower` (`src/compiler/syntax/expressions/operators.ts`)
- strip outer parentheses from an `Expression` → `unparenthesized` (`src/compiler/syntax/expressions/readings.ts`)
- strip outer parentheses from a `Pattern` → `unparenthesizedPattern` (`src/compiler/syntax/patterns.ts`)

- strip outer parentheses from a `TypeNode` before asking its kind → `unparenthesizedType` (`src/compiler/syntax/types/index.ts`)
- check whether a node writes a type, a function type's rest included, never by a list of kinds of your own → `isWrittenType` (`src/compiler/syntax/types/index.ts`)
- read a `QualifiedName` from an `Identifier` or non-optional `MemberAccess` chain → `qualifiedPath` (`src/compiler/syntax/expressions/readings.ts`)
- read what a call or a deferred call (`CallingNode`, `src/compiler/syntax/expressions/calls.ts`) calls by name, the type arguments and the arguments it writes, whether it calls through `?.`, or find the node making the call a node is the callee of among its holders, through type arguments after it or a deferred call's taker → `calledName`, `callTypeArguments`, `writtenArgumentsOf`, `callsThroughOptional`, `callOfCallee`, `makerOf`; the call a deferred call defers, whether an operand has a taker's shape → `deferredOf`, `isTakerShaped` (`src/compiler/syntax/expressions/readings.ts`); the memoized lambda a deferred call's function reads as, and back → `deferredLambdaOf`, `deferredCallOf` (`src/compiler/syntax/expressions/deferred-functions.ts`); an expression's type arguments stand only on a `TypeApplication` (`f<Int>`), a call's callee among them, never on the `Call`, and an optional call's `TypeApplication` callee is a value, its type arguments no call's

## One-way rules

- Shared desugaring (`taggedCall`, `fieldsFunctionOf`, `comparisonLinksOf`, `placePath`, `destructuringOf`, `nullishOf`, `deferredLambdaOf`) lives in `src/compiler/syntax/`. A sugar is given its meaning once, as a memoized core reading there or one record the checker makes (`CheckedBody.builtLiteralOf`), and later phases handle the core form; never a handler per phase for it (lowering's deferred-call entry is a known copy until lowering reads the flow IR, `docs/audit/dry-review-2026-11-13.md` root cause 1). `??`, `?.`, `?->` and `?` are operators of their own typing, no sugar.
- A declaration's members are read through `membersAsWritten`, and which names a node declares or which nodes lay out items one per line are syntax's to say once; editor and formatter kind lists of their own (`name-types.ts`, `outline/`, `placeholder.ts`, the formatter's `itemLists`) are known copies that miss newer kinds (finding 11).
- A link reads through an optional when its node `isOptional` (member access, tuple element, index, call, `->`); its operator is spelled by `linkOperator`/`optionalOperatorOf` (`chains.ts`), never as a literal.
- Node fields hold only nodes, node arrays, optional nodes/arrays, a span, a record of words (a function's `qualifiers`) or primitives, so `childrenOf` (`tree/index.ts`) derives traversal automatically: a child is an object with a `kind` and a `span` (`isNode`).
- A node's span is anchored to its segment (`AnchoredSpan`, `positions.ts`): offsets of different segments never compare, and text positions come only through the tree (`spanIn`, `extentIn`). A function's own span covers its header alone, as does a top-level trait's whose members stand on lines of their own; use `extentIn` for all a node covers.
- In `src/compiler/parser/`, a bracketed construct uses `parseEnclosed`, a list `parseList` / `parseDelimited` (`recovery.ts`, which enters the cursor's list region), and recursive entries use `nested` (`nesting.ts`).
- Where a line break separates two items of a list (spec §2) has one home, `layout/item-breaks.ts`: `breakSeparatesItems` (the next line can start an item, asking the cursor's `startsLineInList`) and `atPostfix` (a postfix bracket attaches only on its operand's line). Ask it only where an item could end: the Pratt `extend` loop, `leveledGrammar`'s loop (types, patterns), the comma list, a lookahead deciding an item's shape by the token after it (struct literal shorthand), and an optional part after a complete item (`& B` after `any A` or a constraint, a range's end) → `continues`, `eatContinuing`. A symbol both prefix and infix starts an item unless a space parts it from the rest of its line, so a lone `..` is an item. What starts an item is derived, never listed: the expression tables (`startsItemOnNewLine`, grammar/expressions/expression.ts) with the item parsers' openers (`spreadOpener`, `grammar/parts/spreads.ts`; `structComprehensionOpener`; `annotationOpener`). A `<…>` list, which nothing pairs, ends at a line heading no deeper than its `<`'s own unless its `>` heads it (`angleListRegion`, `cursor/`), as a bracket left open ends (`cursor/brackets.ts`).
- An indented value is checked, lowered, computed and offered as the literal checking built it as (`CheckedBody.builtLiteralOf`): a phase meeting an `IndentedValue` reads that literal, never its entries a second way. Which literal is the checker's one decision (`checker/constructs/expressions/literals/indented-values.ts`, from the type, else `untypedForm`).
- What separates a block's items on one line is its `ItemRules.separator` (`ItemSeparator`, `recovery.ts`; spec §2): `;` for statements and a module's declarations, `,` for every list (fields, variants, trait members, constraint entries), `'lineBreak'` for cases. Entries in braces are a list (`parseItemEntries`, layout/index.ts): `,` or a separating line break, with each entry's annotations. Layout (`layout/index.ts`) reads either separator and reports the wrong one once (2038, 2039), as `parseCommaSeparated` reports a `;` between bracketed items; no other site tests for a separator.
- A word a grammar position starts with is listed once, in `src/compiler/syntax/tokens/grammar-words.ts`: the parser's table for that position `satisfies StartParselets` (keywords) and `WordParselets` (contextual words) of the list, and completion offers the list, never one of its own (`editor/language-service/completion/places/grammar/words.ts` names only the words that need surroundings, `wordNeeds`).

## Recipes

### Add a word a grammar position starts with

1. Add it to the position's list in `src/compiler/syntax/tokens/grammar-words.ts`. A head's new modifier goes in its group in `modifierGroups` (`syntax/tokens/modifiers.ts`) instead, and the lists, `followers`, the parser and every printer read it from there; the VS Code grammar's `modifier` rule lists a contextual one.
2. Give it a parselet in that position's table: a keyword in the table by token kind, a contextual word in the position's `WordParselets`, declining with `undefined` where what follows makes it a name. Either table fails to compile until it does. A statement word also needs its place in `statementWordPlaces` (`syntax/items.ts`).
3. Completion offers it there with no edit; add it to `wordNeeds` (`completion/places/grammar/words.ts`) only if it means something in some surroundings alone.

### Add a syntax node kind

1. Declare the interface extending `NodeOf<'Kind'>` in `src/compiler/syntax/` and add it to its union in `src/compiler/syntax/tree/index.ts`.
2. Parse it in `src/compiler/parser/` using `nested` (`nesting.ts`) and `parseEnclosed` / `parseDelimited` (`recovery.ts`).
3. Add its handler to every exhaustive `Handlers` table across `binder/`, `checker/` (including `rules/flow/build/`'s `expressionFlows` and `statementFlows`), and `lowering/`.
