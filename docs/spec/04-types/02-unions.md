# 4.2 Unions

**Unions.** A value of the union `A | B` is a value of one of its members, which may be any types: primitives, literal types, structs, enums, shapes, tuples, function types, `any` types and type parameters.

- **Precedence.** In a type, `|` binds looser than `?` and type arguments, and tighter than a function type's `->`: `fn() -> A | B` returns `A | B`, and `(fn() -> A) | B` holds a function type. `any A & B | C` is `(any A & B) | C`.
- **A set.** Order doesn't matter, a member that is a union gives its members (a recursive alias's union too, §4.6: `Tree | String` holds `Tree`'s members and `String`), duplicates merge, `Never` drops out, and a union of one member is that member. A union equal to a recursive alias is that alias: `Json | Int` and `Json?` are `Json` (§19.2). A member that another member holds whole merges into it, so no value sits in two members: a literal type into its base type (`"a" | String` is `String`, `true | false` is `Bool`), and a type into an `any` member whose traits it meets (`Int | any Stringable` is `any Stringable`). A struct declaration and its shape stay apart, since the conversion from one to the other rebuilds the value as another type (§5.2).
- **Collapse.** Substituting type arguments (§8.1) merges members again, as the union written with them would: `T | Int` with `T = Int` is `Int`, `T?` with `T = Int?` is `Int?`, and `T | any Stringable` with `T = Int` is `any Stringable`, which a value of `T` then goes into. A value an `any` member took whole is still a value of its own type inside it, so code written for the merged union reaches it as code written for the members does: it goes in through that member, a pattern naming its type or its literal selects it there (§11.3), and a type whose `any` member took `None` is optional (§10.4).
- **`T?`** is `T | None`, so `T??` is `T?`, and `Map<K, V?>.get(k)` gives a `V?` in which a missing key and a stored `none` look alike; `has(k)` tells them apart. `none` needs no expected type: alone, its type is `None`.
- **Conversion into a union.** Where a union is expected, a value goes into the member of its own type, else into a member written with a type parameter that its type fills (§8.1), else into the one member it converts into by another conversion of §4.1, so an `Email` goes into `(any Notifier)?` as an `any Notifier`. Converting into several members is a compile error. A union goes into a union holding each of its members, a literal member's base, or an `any` member that takes it whole: `Int | Plain` goes into `Plain | any Stringable`. The conversion takes a value once, and reaches inside another type as that type's variance allows (§8.1), never through a reference (§7.3) or inside a handle: an `Array<Int>` is an `Array<Int | String>`, a `Slot<Int>` no `Slot<Int | String>`.
- **Built from the expected type.** Where a union is expected, whatever takes its type from the expected one, a struct, array or map literal, a lambda, a bare variant name or a literal, takes it from the one member it fits; fitting none, or several, is a compile error. `Entry{key: "sent", value: "ok"}` against `Entry<"draft", Int> | Entry<"sent", String>` builds the second, and `[]` against `Array<Int>?` an empty array.
- **Never inferred.** A union is a type only where one is written: without one expected, an `if`'s branches (§10.1), a collection literal's items (§3.3) and a type parameter's arguments (§8.1) still need one type. `const x: Int | String = if c: 1 else: "a"` checks, and `const x = if c: 1 else: "a"` is an error. Values one of whose types holds the others, its values taking theirs (§8.1), agree on that type in any order: `if c: xs else: ys` is an `Array<Int?>` for `xs: Array<Int>` and `ys: Array<Int?>`, whichever branch comes first. The one exception is `None`, as in Kotlin, Swift and C#: where several values take one type and none is expected (§10.1), values that may be `none` agree on the optional of what the others agree on, each wrapped into it, in any order. `if c: 1 else: none` is an `Int?`, `[none, ...xs]` an `Array<Int?>` for `xs: Array<Int>`, and a function returning `none` on one path and an `Int` on another returns an `Int?`.
- **Using one.** No field, method or operator of a member applies to a union; a union of literals has its base type's, through the conversion of §4.3. A union is taken apart with `match` or `is` (§11.3), or used through a trait (§8.2).
