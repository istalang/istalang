# 19.2 Standard modules

The **standard library** is a set of modules, imported explicitly, for example `import * as time from 'time'`. Pure modules are plain code in the language; runtime-backed ones declare externs the runtime implements. Nothing in it reaches a file system, shell, environment, network or reflection: a workflow affects the outside world only through externs its operator provides.

| Module | Contents |
| --- | --- |
| `time` | `Time`, `Duration`, `now()`, `at(t)` (the runtime's only time primitive) and `delay(d)`, which is `at(now() + d)`, both generic over their mark, `K fn delay<K in Persistence>(d: Duration) -> Future<Unit, K>`, so a timer is of the kind of the code making it (§9.2); `t + d`, `d + d` and `d * n` for an `Int` `n`; both types are `Comparable`, as the milliseconds they hold, and `Stringable` and `Parsable` in ISO 8601, `Time` as JavaScript's `Date.toJSON` writes it (`2026-10-25T12:00:00.000Z`) and `Duration` as `Temporal.Duration` does (`PT1H30M`). Time zones: `Zone`, an IANA zone, a type the runtime implements that holds the zone's canonical id, so `==` and map keys compare zones, read by `Zone.parse(id)` in any case, given by `utc()`; `DateTime`, a wall-clock reading with no zone, `Stringable` and `Parsable` as `2026-10-25T13:00:00`, with `weekday()` (1 is Monday, 7 Sunday) and `addDays(n)` (calendar days, so a wall-clock time survives a change of offset); `t.inZone(z)`, the reading of `t` in `z`; `Time.of(dt, z)`, the instant `dt` reads in `z`, the earlier of two where a change of offset repeats `dt` and moved forward by the gap where one skips it, which panics on a date that doesn't exist; and `t.format(z)`, ISO 8601 with `z`'s offset (`2026-10-25T13:00:00.000+01:00`), which `Time.parse` reads. Zone rules are the host's time-zone data, so two hosts with different data can disagree |
| `math` | `abs(x)` of an `Int` or a `Float`; `floor(x)`, `ceil(x)` and `round(x, mode = Rounding.HalfEven)` of a `Float`, which keep its type, so `Int(math.floor(x))` is the int at or below `x`; `sqrt(x)` of an `Int` or a `Float`, a `Float`, NaN for a negative number as IEEE 754 gives; `min(a, b)`, `max(a, b)` and `clamp(self, low, high)` of any `Comparable` type, each giving the first of equal arguments, and `clamp` panicking when `low > high`; `Rounding`, the rounding modes `math` and `decimal` share: `Floor`, `Ceiling`, `TowardZero`, `AwayFromZero`, `HalfEven` (a tie goes to the even neighbour) and `HalfAwayFromZero`. Each function takes its number as `self`, so one imported by name is also a method: `x.abs()`, `x.round()`. Powers are the `**` operator (§10.2) |
| `decimal` | `Decimal`, an exact decimal number of any size, for arithmetic such as money. `Decimal(i)` converts an `Int`, and `Decimal.parse(s)` reads an optional `-`, digits and an optional fraction, such as `-12.50`, and nothing else. A value has one form, so `==` and map keys compare numbers: `toString` writes it with no exponent, no trailing zeros after the point and no `-0` (`-12.5`), and `toFixed(places, mode = Rounding.HalfEven)` with exactly `places` digits after the point (`-12.50`); it crosses as JSON as text (§17.4). Every function of two numbers takes a `Decimal` or an `Int` on either side, never a `Float`, whose rounding is what `Decimal` avoids (`==` is built in and compares two values of one type, so `d == Decimal(1)`, §10.2): `+`, `-` and `*` are exact; `/` rounds half to even to 34 significant digits, as IEEE 754's decimal128 does, and `divide(a, b, places, mode = Rounding.HalfEven)` rounds to `places` digits after the point; `//` and `%` are related as on `Int`s (§10.2); a division by zero panics, there being no infinite `Decimal`. `Int(d)` truncates toward zero and `Float(d)` is the nearest float. `abs`, `floor`, `ceil` and `round(places = 0, mode = Rounding.HalfEven)` give a `Decimal`, and `d ** n` is exact for an `Int` exponent of at least 0 and divides as `/` does for a negative one, so a `Decimal` is `Powerable<Int>`. A negative `places` panics |
| `strings` | String methods, with JavaScript's names and counting code points as `s[i]` does (`includes` is the prelude's, since `in` calls it, §10.2): `indexOf(search, from = 0)` (`-1` when absent), `lastIndexOf`, `startsWith`, `endsWith`, `slice(start = 0, end = none)` (clamping, a negative index counted from the end), `split(separator)` (an empty one splits into code points), `trim`, `trimStart`, `trimEnd`, `padStart(length, fill = " ")`, `padEnd`, `repeat(n)` (panics on a negative `n`), `replace(search, replacement)` and `replaceAll`, which match plain text; `toUpperCase` and `toLowerCase`, by Unicode's default case mapping and never a locale, so a re-run segment always computes the same; `format(template, ...values)`, its values `String`s, where `{}` takes the next one, `{n}` value `n` and `{{` and `}}` write a brace, and a placeholder without a value or a stray brace panics; `graphemes(s)` for user-perceived characters and `utf16Length(s)` for the length JavaScript counts. Called as `strings.trim(s)`, or as `s.trim()` where `trim` is imported |
| `json` | `Encodable` and `Decodable`, the traits of types that cross as JSON (§8.4, §17.4), with their `toJson` and `fromJson` for every primitive, `Json`, `Array`, `T?` and `Map`; `stringify(v)` and a typed `parse<T>(s) -> Result<T>`, through them; `Json`, the recursive union `None | Bool | Int | Float | String | Array<Json> | Map<String, Json>` (§4.6) holding JSON of any shape, written as plain values at any depth (`const j: Json = ["a": 1, "b": [true, none]]`, or the same as an indented value) and taken apart by type patterns (`case Int as n`, `case Map<String, Json> as fields`, `case None`), a JSON number an `Int` where it is whole and a `Float` otherwise, so `Json?` is `Json`, and `has(k)` tells a missing key from a stored `null`; with `encode(v) -> Json` and `decode<T>(j) -> Result<T>` between it and typed values; `encodeText(v)` and `decodeText<T>(j, path)`, the codecs of a type that crosses as the text its `toString` writes; the `JsonName`, `JsonSkip` and `JsonBigInt` annotations (§5.5) |
| `endings` | The std's own: `resultOfEnding`, how a call the runtime ran apart ended, as the code waiting on it reads it (§17.1). Importable like any std module, though no program needs it |
| `lifetimes` | The annotations saying what the std's natives hold and keep, which no code shows (§5.5, §16): `Holds<T>`, on an extern struct, says a value of it holds what a value of `T` holds, a tuple listing several types and `()` none, where it would otherwise hold its type arguments; `Keeps`, on a function, maps each parameter's name to the names of the parameters whose values it comes to hold, where otherwise a parameter taken by `&` keeps every other and nothing else is kept; on one with a body, it stands for the body, which calls code the analysis can't follow. The prelude imports them; they stand only on the std's declarations. `holder<M in Mark>()` gives a `Holder<M>`, a shared struct keeping what its `it` is given, of any type, for as long as it lives: `hold.it start(job)` calls `start(job)` now and keeps its future; when the holder is released, what it keeps is released last first (§16), a disposable disposed and a future cancelled. Where it is declared decides how long that is. Its mark is what it keeps may be of: `holder<"ista">()` in ista code keeping ista futures, as a mark nothing fixes settles to simple (§9.2). A holder that would come to keep itself is the cycle error (§16) |
| `regex` | Regular expressions with RE2's linear-time engine and syntax: flags inline (`(?i)`, `(?m)`, `(?s)`), named groups `(?P<name>…)` or `(?<name>…)`, and no backreferences or lookaround. `Regex{pattern}` is a plain struct, so `Regex{"\\d+"}` is a literal one, which panics where it is used if the pattern is invalid; `Regex.parse(text) -> Result<Regex>` checks a pattern from outside. It is `Stringable` and `Parsable` as its pattern, and crosses as JSON as text (§17.4). `test(s)` (a match anywhere), `find(s) -> Match?`, `findAll(s) -> Array<Match>`, `replace(s, replacement)` and `replaceAll`, which expand `$1`, `$<name>`, `$&` and `$$` as JavaScript does, `split(s)`, and `escape(s)`, the pattern matching `s` literally. A `Match` has the `text` matched, the `index` it starts at in code points, `captures: Array<String?>` (group `n` is `captures[n - 1]`, `none` when it took no part) and `named: Map<String, String>`, the named groups that took part |
| `crypto` | `hash(algorithm, data, encoding = Encoding.Hex)` and `hmac(algorithm, key, data, encoding = Encoding.Hex)`, with `algorithm` a `Hash` (`Sha1`, for interop with older systems only, `Sha256`, `Sha384` or `Sha512`); `timingSafeEqual(a, b)`, which takes the same time whatever two strings of one length hold, and is `false` for strings of different lengths; `encode(text, encoding)` and `decode(text, encoding) -> Result<String>`, with `encoding` an `Encoding` (`Hex`, `Base64`, or `Base64Url`, unpadded). There is no bytes type, so text goes in as its UTF-8, a key included, and digests come out as text; `decode` fails on text that isn't the encoding's canonical form, or whose bytes aren't UTF-8 |
| `random` | `integer(range)`, uniform over the ints a range with both ends reaches, its step included (`random.integer(1..=6)`, `random.integer(0..100 by 5)`), which panics on an empty or open one; `fraction()`, a float uniform from 0 up to 1, written over `integer`; and `uuid()`, a version 4 UUID (RFC 9562) in lowercase. The draws come from a secret seed and a count kept in the snapshot, so a segment that runs again draws the same values (§14), and they are unpredictable enough to serve as tokens. A spawned instance's seed is drawn from its parent's (§17.1) |
| `log` | `debug`, `info`, `warn` and `error`, each taking a message and optionally `fields` of any `Encodable` type, as in `log.info("charged", struct{amount, card})`, all through one extern, `write(level: Level, message: String, fields: json.Json)`, so mocking `write` captures every log (§18). A record, holding its level, message, fields, instance and its segment's start time, reaches the host when its segment commits (§17.3); a segment that is discarded logged nothing |
| `runtime` | `id()`, the instance's name: a context's key, a spawned instance's, or a live run's as its host started it (§17.1); `version()`, the content hash of the program it runs, which is fixed for its life (§14); `commit()`, an already-resolved future: `await runtime.commit()` commits without waiting; `isolate(f)`, which runs `f`, a sendable function taking nothing, as an instance of its own and gives a `Future<Result<T>, "ista">`: `f`'s result, or its panic as an `Err` (§17.1); and `delegate(job)`, ista code's effects (§14); for live code, `hostStore()`, `Runtime.open(store)`, a runtime's `call(key) f(args)` giving a `Call<R>`, and `run(key) f(args)`, which run ista code in contexts (§17.1) |
| `inbox` | `Inbox<T>`, a FIFO message queue built on slots, with `send`, `sendRevertible`, `receive` and `pending`, and `Revertible<T>`, the holder of a revertible message (§15.3) |
| `collections` | `WeakMap<K is Disposable, V>`, a shared struct keeping an entry only while its key is alive, with `WeakMap.create<K, V>()`, `get(k) -> V?`, `set(k, v)`, `has(k)`, `includes(k)`, the same test, which `in` calls, and `delete(k)` (whether it held `k`). It is built on `WeakRef` and `disposed()`: each entry holds a future that waits for its key's `disposed()` and then deletes the entry, so the entry and its value are released when that future resumes, after the segment that disposed the key. Like JavaScript's, it can't be listed or counted |
| `futures` | Combinators written in the language, each once over the kind, `K fn …<…, K in Persistence>` (§9.2, Mark parameters), so futures of two kinds in one call are an inference error. They are written over `first<T, K>(fs: Array<Future<T, K>>) -> First<T, K>`, an awaitable of mode `K` that races a list of futures once it is awaited: its `onAwait` registers a `Resolver.at` of its resolver on each (§15.2), so it decides as a `select`'s cases do (§15.4): it gives the position and value of the first to arrive, the lowest position among those resolved before the await, the first the event resolves among those resolving together (§15.2), and the others take nothing; it panics, awaited on an empty list, and disposes none of them. The others are async functions, which watch their futures from the call on: each future is awaited in a call of its own, so it keeps its place in its slot's queue between two arrivals, and those waiting for several arrivals await a `First` of those calls still out, turn after turn. A failure is a `Result`, so the combinators that stop early read `Ok` and `Err`: `all(fs)` gives every `Ok` value in position order, or the first `Err` as soon as it arrives (`Result<Array<T>, E>`); `allSettled(fs)` every value in position order, once all resolved; `race(fs)` the first value, and panics on an empty list; `any(fs)` the first `Ok`, or every error in position order once all failed (`Result<T, Array<E>>`); `quorum(n, fs)` the first `n` `Ok` values in the order they arrived, or the errors once `n` can't be reached (`Result<Array<T>, Array<E>>`), and panics unless `0 <= n <= fs.length()`; `timeout(f, d)` the value, or `none` if `d` passes first (`T?`); `retry(attempt, times = 3, backoff = 1s)` calls `attempt`, a plain or `async` function returning a `Result`, up to `times` times, waiting `backoff` before the first retry and twice as long before each next one, and gives the first `Ok` or the last `Err`; it panics when `times < 1`. Like `first`, none disposes a future it is given: it lets go of them when it returns, so a loser nothing else holds, such as one created in the call's own statement, is disposed once that statement has ended and the combinator returned, while one held in a variable lives on (§16) |
| `rpc` | `create<P, R>()` makes a `Method<P, R>`. `m.call(msg)` returns a `Future<Result<R>, "ista">`: the reply, or an `Err` with code `unanswered` when the call is let go without one, because the server handling it is disposed or the method dies with the call still queued. A call is sent revertibly and held while its caller waits, so one whose caller lets go of it before a server takes it, such as a loser of a `select` (§15.4), is withdrawn; waiting callers don't keep the method alive. `m.onMessage(handler)`, for a plain or `async` handler from `P` to `R`, serves calls one at a time in the order they arrived, the handler's return value being the reply, until the future it returns is disposed. Several servers of one method share its calls, each call going to one of them. Calls queue in an inbox, and each reply travels in a one-shot slot. |
| `fanout` | `create<M>()` makes a `Bus<M>`, disposable like an inbox. `bus.subscribe(handler)`, for a plain or `async` handler of `M`, returns a `Future<Unit, "ista">` that runs the handler for each message sent after the call, in the order they were sent, one at a time, until it is disposed, or until the bus is disposed and it has handled every message sent before; a subscription doesn't keep the bus alive. `bus.send(msg)` delivers a message to every subscriber, and `bus.sendRevertible(msg)` returns a `Revertible<M>` (§15.3) whose release retracts the message from every subscriber that hasn't read it yet. Messages form one stream of slots that every subscriber reads. |
| `testing` | Test modules only (§18): the `Suite` annotation and `Test`; `mock` and `Mock<F>`; `spawnCrashingEveryAwait`, an `Instance`'s inspection (`idle`, `reaches`, `waitingAt`, `state`) and `InstanceState`; `handle<T>()`; and the test library: `test`, `group`, `skip`, `only`, `Setup`, `setups`, `FakeClock`, `FakeQueue`, `assert`, `assertEq` and `expectPanic` |

```ista
# from the time module
struct Duration:
    value: Int              # milliseconds

struct Time:
    value: Int              # milliseconds since the Unix epoch

fn add(left: Time, right: Duration) -> Time:     # Time + Duration
    Time{value: left.value + right.value}
```
