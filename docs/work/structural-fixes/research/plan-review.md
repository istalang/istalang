2. **Step back / Single source of truth (`Clean Dev: Step back`, `B.4 Fix cause, not symptom`) — `B1` conflates generic declaration-level graphs with concrete instance closing, and misdiagnoses `B70`, `B18`/`B81`, and `B87`** at `plan.md` §B, `b1.md`
   - **Evidence in code (`b1.md` is inaccurate against the code on four counts, so a fresh agent following it will hit walls):**
     1. **Generic vs. concrete domain mismatch:** `b1.md` asks for *"one enumerator on the checker surface... Given an instance (a function or type with its type arguments), it lists what instantiating it demands... Route type expansion, function expansion, lifetimes' callees, data kinds and lowering's closing through it."*
        - `rules/expansion/types.ts`, `rules/expansion/functions.ts`, `rules/lifetimes/lifetimes.ts`, and `rules/kinds/data-kinds.ts` do **not** run on concrete `FunctionInstance`s; they run on **uninstantiated generic declarations** (where `T` is a `TypeParameterType` and a `RequirementCall` on `T` has no witness yet). Lowering (`witness-closing.ts`, `closed-calls.ts`) closes concrete `FunctionInstance`s with concrete `Witnesses` and field-loop `passes`. One function taking `(declaration, typeArguments)` cannot serve both without separating what a *generic declaration* reaches from how a *concrete instantiation* closes it.
     2. **`B70` ("A default lambda with a written signature types its field from the signature, without checking its body first") is unsound in Istalang:**
        - In Istalang (`constructs/closures/lambdas.ts:353-366`), a lambda's `FunctionType` carries `send` (`sendable`/`inert`/`plain`, derived from `capturedSend` over the body's captures—and a field default sees prior fields, §3.1) and `mark` (`nestedValueKind`, derived from `scope.reliesOnKind` over the body's calls). Syntax alone (`fn(a: A) -> Int`) does **not** determine a lambda's type without checking its body.
        - **Actual root cause of `B70` in code:** `Layouts.#fields` (`constructs/declarations/layout/index.ts:81-90`) and `Parameters.#types` (`constructs/declarations/functions/parameters.ts:106-124`) are two whole-declaration `EntryTable`s that call each other (`#fields(A)` → `#types(fieldsFunctionOf(A))` → `#together(fieldsFunctionOf(A))`). When `f`'s default reads `a.x` (`Int`), `fieldOf` calls `fieldsOf(A)` → `#fields.get(A)`, closing a Tarjan SCC across `#fields(A)` and `#types(fieldsFunctionOf(A))`. Even though `#fields` has a silent `standIn` (written fields `[x: Int, f: errorType]`), Tarjan marks **every** entry in the SCC as `member = true`, firing `reportMember` (`5112 defaultCycle`) on `#types` and discarding `f`'s inferred type! This happens even if `f = fn(a: A): a.x` (no written `-> Int`) or `y = helper(a)`.
     3. **`B18`/`B81` re-entrancy trap:** In `layout/index.ts:211`, `#fieldsOf(declaration)` runs `declaredFields` (which checks defaults) **before** `#ended` (`#expansion.endlessFieldsOf`). In `B18` (`struct A<T> { b = B<T>{a: none} }`, `struct B<U> { a: A<(U,)>? }`), checking `A`'s default `B<T>{a: none}` enters `#fields.get(B)` → `endlessFieldsOf(B)` → `#edges.get(A)` **while `#fields.get(A)` and `#types.get(fieldsFunctionOf(A))` are still running on the stack**. If `#edges.get(A)` reads `declaredFieldsOf(A)` or `parametersOf(fieldsFunctionOf(A))`, it receives their cyclic `standIn` (`b: errorType`), missing the `A -> B` edge and triggering a false `5112 defaultCycle` on `A` via Tarjan! `b1.md` must specify the non-reentrant separation (e.g., `#fields` resolves types first without `#ended`; `endlessFieldsOf` masks fields in `fieldsOf` / `declaredFieldsOf` after, or per-field entries avoid the declaration-wide SCC).
     4. **`B87` is not an callee-enumeration bug:** `lifetimes.ts:#calleesOf` already includes `witnessCallsOf(call.witnesses)` and `analysis/calls.ts:66` already calls `checkEscapingCalls` on `made.call.witnesses`. `B87` (`fn settle<T is Homed>(t: T, n: Node): t.homeOf()->node = n`) fails because `Door.homeOf` has no writes of its own (it just returns global `homes`), while `settle<T>` writes `n` into the result of `t.homeOf()`. Because `operations.ts:138` treats `t.homeOf()` on type parameter `T` as `unknownCall` (a fresh local temporary, not an `Input` of `settle`'s `Summary`), `settle`'s summary records no requirement on what `t.homeOf()` returned, so `applySummary` at `settle(door, n)` never connects `Door.homeOf`'s result (`homes`) to `settle`'s write (`->node = n`). Fixing `B87` requires representing a requirement call's / required field's result in `Summary` (or closing requirement calls against `call.witnesses`), not a surface enumerator.

4. **Fix cause, not symptom (`Clean Dev: B.4`, `B.5`) — `d1.md`'s diagnosis of `B88`, `B68`, `B69`, and `B91` points the implementer at the wrong mechanisms** at `plan.md` §D, `d1.md`
   - **Evidence in code (each of the four bugs in `d1.md` has a small, exact cause in the code that differs from `d1.md`'s prose):**
     1. **`B88` (`scope-protocol.ts`):** `d1.md` says *"A construct's standing comes from what it resolves to, not from its syntax kind."* But `BodyScopes.checking` (`body-scopes.ts:81`) calls `placeOf`/`standingOf` **before** the expression's handler runs (before resolution). The actual fix is simply giving `MemberAccess`, `Binary`, `Unary`, and `Index` the `'opens'` standing in `scope-protocol.ts:68-97` (just like `Call: opens`; when a `MemberAccess` is a plain field read, opening/joining a scope without calling `scopes.join` is a zero-cost no-op).
     2. **`B68` (`takesLive(logged(area))`):** `d1.md` says *"The outer call settles only after its postponed inner arguments are bound."* In fact, `area` *cannot* be bound before `takesLive` chooses—`logged<...A, R>(f: Fn<A, R>)` only learns `A = (Int,)` and `R = Int` from `takesLive`'s parameter `f: fn(Int) -> Int`! The actual bug is in `src/compiler/checker/types/type/function-types.ts:189-219` (`sameShape`): it matches a pack on `declared` (`declared.pack !== undefined`) against `given.parameters`, but rejects a pack on `given` (`given.pack = A_logged` from `logged(area)`) when `declared.pack === undefined` (`given.parameters.length >= fixed` fails `0 >= 1`, and line 206 requires `given.pack === undefined`). Making `sameShape` symmetric when `given.pack !== undefined` binds `A_logged = (Int,)` during `takesLive`'s choice.
     3. **`B69` (`queueUp work(1)`):** `deferred-calls.ts` already desugars `queueUp work(1)` into `queueUp(given: { const v0 = 1; fn(): work(v0) })`, and `ConstraintScope.#judgeAll` already judges that lambda *after* `queueUp` is chosen (`expected = ista async fn() -> Int`, `orFuture = Future<Int, "ista">`). It fails with `5001: Expected Int, found Future<Int, "ista">` because inside the lambda, `work(v0)` joins the still-open `ConstraintScope` with `tail.type = Future<Int, K_work>` (`K_work` still unsolved), and `ReturnScope.#settled` (`constructs/closures/returns.ts:173-184`) immediately checks `fitsEach(this.#orFuture)` (`fitOf(Future<Int, K_work>, Future<Int, "ista">)`) **before** `K_work` is solved! That returns `false` on unsolved `K_work`, so `#settled` picks `result = Int` instead of `this.#orFuture = Future<Int, "ista">`.
     4. **`B91` (`From.Fn(key)`):** `d1.md` says *"Bind a type parameter that is used only under an associated type in a parameter position, as B91 needs."* **Do not invert associated types in inference**—associated types are non-injective (`equal.ts:173` banner: *"inference never looks through an associated type"*). In `B91`, `R` *is* bound by the expected return type `From<Q>` (`applied-call.ts:121`); `chooseCall` rejected `From.Fn(key)` before reaching line 121 because function parameters are **contravariant**: `functionFitsByParts` (`fit/parts.ts:137`) calls `fits(taken = R.Seen, given = Q.Seen)`, which enters `relatedByParts(expected = Q.Seen, found = R.Seen)` in `types/inference/relate.ts:220`:
        ```ts
        if (isComputed(expected)) {
          return mentionsVariable(expected, relating) || sameType(expected, found);
        }
        ```
        Because contravariance put the inference variable `R` in `found` (`R.Seen`) and the rigid parameter `Q` in `expected` (`Q.Seen`), `mentionsVariable(expected, relating)` is `false`! Checking `if (isComputed(expected) || isComputed(found)) { return mentionsVariable(expected, relating) || mentionsVariable(found, relating) || sameType(expected, found); }` fixes `B91` in one line without violating associated-type opacity.
   - **Wave impact:** Once `d1.md` points at those four exact files (`scope-protocol.ts`, `function-types.ts`, `returns.ts`, `relate.ts`, `type-text.ts`), notice that **D1 is completely disjoint from C1** and can run in **Wave 1** in parallel!

### CORRECTNESS

1. **`b1.md` (`B1` generic requirement expansion):** In `src/compiler/checker/surface/resolved-call.ts:190`, `functionCallsWithin(call)` returns `[]` when `call.kind === 'requirement'`, dropping `witnessCallsOf(call.witnesses)`. Furthermore, when a generic function `f<T is Loop>(t: T)` makes a `RequirementCall` `t.step<(T,)>()` where `Loop.step<U>` is generic, the expanding argument `(T,)` is on the `RequirementCall` (`call.typeArguments`), while the witness `S.step<V>` is attached to the caller of `f<S>` (with `typeArguments: [V]`, where `V` is `Loop.step`'s `U`). To catch `B1`'s cycle in `rules/expansion/functions.ts`, either `RequirementCall`s must contribute edges through the trait requirement node (with `conformance.ts` adding edges from the trait requirement's parameters to the chosen witness's), or `closedInside` must be run when expanding `call.witnesses`. ### ROOT CAUSE & SYSTEM-DESIGN OBSERVATIONS

1. **Scout-symptom prose vs. mechanism-first phase specs:** The phase docs (`b1.md`, `c1.md`, `d1.md`) inherited hypotheses from the triage scouts before tracing the exact failure lines (`relate.ts:220` contravariance for `B91`, `function-types.ts:206` asymmetric pack check for `B68`, `returns.ts:175` premature `fitOf` on an open scope variable for `B69`, `operations.ts:138` unlifted requirement-call result for `B87`, and the `#fields` ↔ `#types` whole-declaration SCC for `B70`/`B18`). When a phase doc prescribes an architectural invention ("decide standing from what a construct resolves to", "bind a type parameter under an associated type", "type a field from a lambda's written signature") for what is actually a 2–5 line asymmetry in an existing unit, the implementer is pushed to add new layers or break invariants instead of fixing the asymmetry and reducing code.
2. **Whole-declaration `EntryTable` granularity (`Layouts.#fields` vs `Parameters.#types`):** `B18`, `B70`, and `B81` all stem from storing all fields of a struct in one `EntryTable` (`#fields.get(A)`) that mutually recurses with all parameter types of `fieldsFunctionOf(A)` (`#types.get(fieldsFunctionOf(A))`) and runs `endlessFieldsOf(A)` inside `#fieldsOf`. Because Tarjan's SCC in `Entries` marks every node in a cycle as `member = true` and fires `reportMember` on all of them, any default reading an *already-known* written field `a.x` of `A` poisons the entire struct's layout and triggers `5112 defaultCycle`. Separating per-field type resolution from whole-struct layout/expansion breaks the false SCC without special-casing lambda syntax.
