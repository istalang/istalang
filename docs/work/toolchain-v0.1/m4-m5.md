# M4 + M5 — Standard library and test runner

Built together: the test runner comes first, and every new std module is tested with it.

## Process

- **S → T1 → T2, sequential.** S fixes the std-module template before anything copies it (D79, D128, D164, D166); T1's `testing` natives are the first copy. T2's library needs T1's runner, and every module phase needs both.
- **Then four ∥ phases, at most 3 at a time,** in worktrees: D, C, B; A when a slot frees. *Why:* D touches the runtime and the snapshot, so it starts first.
- **Per phase:** implementer fork, then cold `qa` and a cold Claude `reviewer`. S skips `qa`: it changes no behaviour, and `stdlib/std-modules.test.ts`, `stdlib/natives.test.ts` and the corpus cover it.
- **End:** e2e `qa` after the last merge, then a merge review of `main` since `8af3f6c`.

## Rules for every phase

- **Spec first.** §3.8 names most modules without signatures. A phase's first step writes its modules' API into §3.8 (signatures, error cases) with proposed defaults for the gaps below, and the human approves it before code.
- **Libraries.** Prefer a maintained library over hand-rolled code (decimal arithmetic, RE2-style regex, Temporal/time zones, hashing). The phase names its pick and why in its report.
- **Errors.** A failure the caller can expect returns `Result<T>`, as `parse` does; a broken precondition panics, as `xs[i]` does.
- **No bytes type in v0.1.** Hashing and encodings take a `string` (as UTF-8) and give text (hex, base64); decoding returns `Result<string>`.
- **Diagnostics.** A new code goes in the block of the rule's owner (binder 4xxx for the import rule, the annotations range for `@Suite`).
- **Tests in the language.** A std module's tests are `src/stdlib/<name>/<name>.test.ista`, run by `ista test`, which `npm run verify` runs (T2 wires it). Compile errors stay corpus cases; TypeScript tests only cover a native's own logic.
- **Acceptance**, beyond each phase's own: every function in its approved §3.8 rows exists and is covered by its module's `.test.ista`, with at least one failing or panicking case per module.

## Shared surfaces and their owners

| Surface | Owner | Consumers |
| --- | --- | --- |
| Std module registration and the native capability shape | S | all |
| §3.8 rows | the phase that owns the module | — |
| Snapshot format | T1 (mock and inspection state), then D (recorded random values and logs) | — |
| `testing` module externs (`mock`, `start`, `handle`, suite runner) | T1 | T2 |
| Test library and `ista test` in `npm run verify` | T2 | A, B, C, D |
| Prelude array/map methods taking functions | B | C |

## Phases

**S — Std plumbing** (structural). One record per std module (name, source, natives), registered in one list. One capability shape, built once per segment. Names spelled once (`staticName`, one module-name home), and `Error` built through its declaration, not by position. *Accept:* adding a std module edits one list; D79, D128, D164 and D166 are resolved and deleted; behaviour and corpus outcomes unchanged.

**A — Numbers.** `math`, `decimal`. *Gaps:* int/float overloads, `round` mode, `floor`/`ceil`/`round` result type, `sqrt` of a negative, `clamp` order; Decimal precision, division rounding, canonical text. *Accept:* table tests cover rounding and precision edges; `Decimal` is Stringable, Parsable, a JSON string, and mixes with `int` only.

**B — Text and collections.** `text`, `regex`, `collections.WeakMap`, and the prelude's function-taking array/map methods (D75). *Gaps:* text API, case locale, `format` syntax; regex flavour, captures, flags; WeakMap API. *Accept:* a catastrophic-backtracking pattern runs in linear time; a WeakMap entry is gone once its key is disposed, across a snapshot.

**C — Futures library.** `futures` (`all`, `any`, `race`, `allSettled`, `quorum`, `timeout`, `retry`) in the language over `first`; `rpc`; `fanout`. *Gaps:* signatures, `timeout`'s result, `retry`'s backoff, disposal of losers. *Accept:* each combinator resumes correctly from a snapshot taken while it waits.

**D — Effects and system.** `random`, `log`, `runtime` (instance id, version), `crypto`, time zones in `time`. *Gaps:* random API and how tests fix it; log levels, fields and the host sink; crypto algorithms; zone API. *Accept:* a re-run segment sees the same random values; a discarded segment emits no logs; crypto matches published test vectors.

**T1 — Test runtime.** The binder rule that only `.test.ista` modules import `testing`; `mock`/`Mock<F>` over the function table; `start` and its inspection (`idle`, `reaches`, `waitingAt`, `state`, `result`); `handle<T>()`; `crashEveryAwait` and panic capture; the `@Suite` runner (a fresh instance per test); `ista test`. *Gaps:* `ista test` is absent from the spec (discovery, filters, output, exit codes); module ownership of `Test`/`Setup`; mocking one target twice; `start`'s argument encoding. *Accept:* a mock replaces an extern, a std and an own function in started instances too, and is released when its holder ends, failure included; a non-test module importing `testing` is refused.

**T2 — Test library.** `test`, `group`, `skip`, `only`, `Setup`/`setups`, `FakeClock`, `FakeQueue`, `assert`/`assertEq`/`expectPanic`, written in the language. *Gaps:* `skip`/`only` semantics, assertion messages, `expectPanic` on async, equal deadlines in `FakeClock`. *Accept:* §10's suite runs under `ista test`, including clock-driven expiry, mocks and `crashEveryAwait`; `npm run verify` fails when a std `.test.ista` fails.

## Out of scope

P2 and P6 (collection and cursor cost): measured against real workflows first, not in M4.
