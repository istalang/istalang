| P1 | Commits dominate the scheduler's cost. Measured in 3.6 (400 executions waiting on one inbox, about 1,200 heap objects, 401 commits): 1.25 s in all, about 3 ms a commit, growing with the square of the executions. About 83% of it is `commit` (scheduler/wake.ts): writing each snapshot through the zod codec and canonical JSON, then reading it back so the next segment restores what a restart would see. Resolving futures, which scans every execution for the ones waiting (scheduler/futures.ts), shows up at a few percent. 3.6 removed the other scans: an execution names its call future, and the heap counts ids up. | P2 | Building a collection one item at a time is quadratic: arrays and maps are immutable plain values, so every append, `push` and `m[k] = v` copies (measured: a 20k-element comprehension ~2.5 s; 5k map inserts ~0.9 s, after each map took over its predecessor's hash table).
